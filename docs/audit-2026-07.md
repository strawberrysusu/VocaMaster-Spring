# 전체 감사 분류 (2026-07-31, Codex 리뷰 기반)

> Codex가 소스 108개 + 테스트 + 마이그레이션 + 문서 전수 검토. 결론: "기본 구현은 탄탄,
> 단 **실제 운영 전에** 고칠 것들이 있음". 현재 운영 전(사용자 0명)이므로 전부 급한 게 아니라
> **바구니 4개로 분류**해서 로드맵에 흡수한다. 원칙: Phase 진행을 멈추지 않는다.

## 🔴 바구니 1 — 이번 주 미니 정비 (작고, 배운 개념 재사용)

1. **[P1-1] Refresh 재사용 감지 후 mass logout이 롤백됨** — `refresh()`가 한 트랜잭션이라
   전체 폐기 후 예외를 던지면 폐기까지 같이 롤백. **면접 메인 무기(reuse detection)가 실제론
   안 도는 것.** 수리: 전체 폐기를 `REQUIRES_NEW`(방금 동시성 테스트에서 배운 그것)로 분리 커밋.
   + 테스트도 "테스트 트랜잭션에 가려지지 않는" 형태로 (ConcurrencyTest 패턴 재사용)
2. **[P1-6] ImportService에 `@Transactional` 없음** — 중간 실패 시 앞부분만 커밋되는 부분 저장.
   Study/Quiz에서 이번 주 한 것과 동일한 한 줄 수리
3. **[P1-3] 화면 로그아웃이 서버 로그아웃 아님** — localStorage만 지우고 `/auth/logout` 미호출
   → refresh cookie·DB 토큰 생존. Mustache에 fetch 한 줄

## 🟠 바구니 2 — Phase 4 진입 전후에 결정 (설계 필요, ADR감)

4. **[P1-4] 학습 이력 있는 카드/덱 삭제 → FK 위반 500** — 지금도 데모에서 재현 가능한 실 버그.
   soft delete vs cascade 정책 결정 필요. Phase 4가 덱 복사/공개를 만지므로 그때 같이 (ADR)
5. **[P1-9] 신형 Quiz 세션 오답이 오답노트/통계에서 누락** — 구형 QuizAttempt만 집계.
   WrongNote aggregator에 신형 포함 or 모델 통합(Phase 6)까지 임시 병합
6. **[P2-20] recordAnswer 최초 progress 동시 생성 → unique 500** — stats에서 upsert로 푼 것과
   동일 패턴. CardProgress 생성에도 적용 검토 (+ 멱등성은 Phase 6)

## 교훈 (테스트 구조)

클래스 `@Transactional` 테스트는 **운영 커밋 경계를 검증하지 못한다** — P1-1이 그린이었던 이유.
트랜잭션 경계 자체가 관심사인 테스트(인증 회전, Import 원자성)는 ConcurrencyTest처럼
`NOT_SUPPORTED` + 수동 정리 패턴으로 작성할 것.
